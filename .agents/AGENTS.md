# Agent Guidelines

> **CRITICAL MAINTENANCE NOTE**: If the codebase shifts (architectural changes, new tech stack, new tooling), always confirm that `AGENTS.md` remains aligned with the current state of the project.

## 1. Canonical Tool Execution Protocol & Precedence

When exploring, analyzing, or modifying the codebase, agents and developers must adhere strictly to the following tool execution precedence:

1. **AST & Language Server Tools (Highest Priority)**:
   * Use `@ast-grep/cli` (installed as a devDependency) for structural code search: `npx ast-grep -p '<pattern>' --lang ts` for ad-hoc pattern matching, `npx ast-grep scan` for rule-based analysis. Prefer AST queries over text search whenever the target is a structural element (function call, import, type reference).
   * Use TypeScript compiler diagnostics (`rtk tsc --noEmit`) to resolve type signatures and cross-references.
   * Do not rely on plain-text string matching or regex when AST tools can resolve the target structural element.
2. **Targeted Symbol & Text Search (Fallback)**:
   * When AST endpoints cannot express the query, leverage targeted ripgrep (`grep_search` / `search_files`) scoped to specific symbol identifiers rather than broad text queries.
3. **Contextual File Navigation**:
   * Read `README.md` and `SPEC.md` prior to inspecting individual implementation files to understand module scopes, file responsibilities, and architectural boundaries.
4. **Targeted Text Inspection**:
   * Inspect specific line ranges or symbols rather than reading entire source files when investigating localized logic.
5. **Command Execution**:
   * **All shell commands MUST be wrapped with `rtk`** to compress output before it reaches the agent context window. See §1.1 for the command mapping.

### 1.1 Agent Efficiency Tooling

Three tools form the agent efficiency layer. All are mandatory for autonomous agents operating in this repository.

#### RTK (Rust Token Killer)

RTK is a CLI proxy that filters and compresses shell output before it reaches the LLM context window, cutting 60–90% of token consumption on common operations. Configuration lives in `.agents/rules/antigravity-rtk-rules.md` (auto-generated by `rtk init --agent antigravity`).

**Mandatory rule**: Always use the most specific RTK subcommand available. Fall back to `rtk npm run <script>` for commands without a dedicated subcommand.

| Raw Command | RTK Equivalent | Notes |
| --- | --- | --- |
| `tsc --noEmit` | `rtk tsc --noEmit` | Type checking without emitting JS |
| `vitest run` | `rtk vitest run` | Automated test runner (only failures shown) |
| `npm run build` | `rtk npm run build` | Vite production compilation |
| `npm run dev` | `rtk npm run dev` | Vite local development server |
| `npm run typecheck` | `rtk npm run typecheck` | Static typecheck |
| `npm run test` | `rtk npm run test` | Vitest test execution |
| `git status\|log\|diff` | `rtk git status\|log\|diff` | Condensed git output |
| `ls <dir>` | `rtk ls <dir>` | Token-optimized directory listing |
| `grep <pat>` / `rg <pat>` | `rtk grep <pat>` / `rtk rg <pat>` | Compact, grouped by file |
| `find <args>` | `rtk find <args>` | Compact tree output |
| `tree <dir>` | `rtk tree <dir>` | Token-optimized tree |

> **Maintaining this table**: When new RTK subcommands become relevant to this project, add them here. Run `rtk help` to discover available subcommands. Run `rtk gain` to review cumulative token savings.

#### ast-grep (`sg`)

`@ast-grep/cli` is installed as a devDependency and provides structural AST search powered by Tree-sitter. Use it instead of regex for any query targeting code structure.

```bash
# Find console statements
npx ast-grep -p 'console.log($$$ARGS)' --lang ts

# Find React useState hooks
npx ast-grep -p 'const [$STATE, $SETTER] = useState($INIT)' --lang tsx

# Find function declarations by name pattern
npx ast-grep -p 'function $FUNC($$$PARAMS) { $$$BODY }' --lang ts
```

#### ponytail (Complexity Reduction Plugin)

The `ponytail` plugin (installed at user level via `.gemini/config/plugins/ponytail`) enforces minimal, simplest-possible implementations. It is auto-loaded by Antigravity.

* **When to use**: Any coding task — writing, refactoring, fixing, reviewing, or choosing dependencies.
* **Trigger words**: "ponytail", "be lazy", "simplest solution", "yagni", "do less".
* **Intensity levels**: `lite`, `full` (default), `ultra`.
* **Companion skills**: `ponytail-review` (over-engineering code review), `ponytail-audit` (whole-repo audit), `ponytail-debt` (track deferred shortcuts).

## 2. Safety, Boundaries & Git Constraints

* **Strict Task Scoping**: Do not modify files outside explicit task boundaries without prior verification.
* **Credentials & Secrets**: Do not commit credentials, secrets, or temporary debug logs.
* **Fail Fast**: If a local build step, typecheck, or test fails, fix the error immediately before proceeding to subsequent steps.
* **Git Safety Rule for Agents**: Automated agents operating in this repository **MUST NEVER** execute `git add` or `git commit` commands on the developer's behalf. Commit creation remains strictly developer-authoritative. Agents must suggest properly formatted Conventional Commit messages (`feat:`, `fix:`, `refactor:`, `docs:`) for human review upon passing all checks.
* **Conventional Commits Standard**: Feature commits and pull requests MUST adhere to Conventional Commits format (`feat:`, `fix:`, `refactor:`, `docs:`, `chore:`).
* **Static Deployment Pipeline**: Production releases are automated via GitHub Actions (`.github/workflows/deploy.yml`), deploying static Vite bundles directly to GitHub Pages on pushes to `main`.
